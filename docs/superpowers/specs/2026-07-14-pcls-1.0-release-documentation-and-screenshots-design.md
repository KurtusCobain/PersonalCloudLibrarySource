# PCLS 1.0 Release Documentation and Screenshots Design

## Status and release boundary

Prepare a complete, polished 1.0 release-candidate documentation set without declaring or publishing version 1.0. The extension manifest and installer history remain at version 0.3.2 until every required qualification row passes. This work must not create a GitHub release, change the package identity, add a 1.0 installer entry, or merge the feature branch automatically.

The final release commit, performed only after qualification, will change the extension version to 1.0.0, add the dated installer package entry and package URL, replace the changelog's `Unreleased` label with the release date, and publish the prepared release notes.

## Audience and story

The primary audience is a Playnite user who owns or controls a personal game library stored locally, on an external drive, on a NAS or mapped share, or behind a user-configured rclone remote. The documentation must explain PCLS as a catalog-and-cache workflow rather than a streaming or content-provision service.

The documentation and screenshot sequence will tell one consistent story:

1. Choose and configure a source.
2. Verify the manifest and cache settings.
3. Import catalog entries into Playnite.
4. Distinguish cached games from remote install-ready games.
5. Install or copy an eligible game into the guarded cache.
6. Monitor queue status and recent activity in Desktop.
7. Use imported games through standard Playnite controls in Fullscreen.
