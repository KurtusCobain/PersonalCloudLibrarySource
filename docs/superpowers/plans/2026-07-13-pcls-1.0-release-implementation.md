# PCLS 1.0 Release-Hardening Implementation Plan

> **Execution note:** Implement this plan only after the audit, matrix, design, and checklist are reviewed and approved. Use `superpowers:test-driven-development` for behavior changes and `superpowers:verification-before-completion` before every pass is declared complete.

**Goal:** Deliver a qualified PCLS 1.0.0 release in small, reviewable passes without rewriting the plugin or adding a dedicated Fullscreen dashboard/setup experience.

**Architecture:** Extract only confirmed risk boundaries—manifest loading/validation/mapping, path/state/deletion policy, queue/execution/notifications, startup/setup state, and release metadata validation—while retaining current working UI and services.

**Tech stack:** C# 7.3, .NET Framework 4.6.2, WPF, Playnite SDK 6.16.0, old-style MSBuild, NUnit/NUnitLite 3.14, PowerShell, Playnite Toolbox.

**Implementation:** Extract pure/testable services in increments. Route import, command policy, install, uninstall, dashboard counts, and verification through the same results. Keep deletion execution separate from authorization and refuse reparse traversal regardless of opt-in.

**Risk:** Blocker-level—filesystem safety and game state are release-critical.

## Task 7: Complete queue execution, cancellation, retry, verification, cleanup, and shutdown

**Purpose:** Give all transfer work one observed owner and deterministic lifecycle.

**Files likely involved:** transfer manager/job/executor/adapters/process runner; install controller; game commands; plugin transfer/navigation partials; settings.

**Tests to add first:** Actual worker concurrency; queued cancellation; active local/rclone cancellation; retry observation and duplicate suppression; worker exception; terminal event once; long progressing rclone; inactivity timeout; process kill; finalization; cleanup failure; queue shutdown/idempotence/no-new-work.

**Implementation:** Evolve the manager into `TransferQueueService` that starts/observes workers. Remove caller-owned execution and retry `Task.Run`. Replace polling with signaling. Use queue-owned partial paths, mandatory verification, atomic finalization, bounded shutdown, and connect/inactivity timeout semantics. Recommended: remove the misleading verification and incomplete-cleanup toggles; if retained by product review, wire and test exact behavior.

**Validation command:** Focused transfer tests; full suite; real disposable local directory transfer; fake runner tests; real rclone smoke test; controlled Playnite shutdown during transfer.

**Completion criteria:** Concurrency limits workers; all tasks are observed; cancellation/retry/shutdown produce one terminal state; no orphan rclone process remains; partial policy is deterministic; healthy long transfers are not killed by total duration.

**Dependencies:** Tasks 4–6.

**Risk:** Blocker-level—data integrity and process lifecycle.

## Suggested commit grouping

Use approximately these reviewable groups, combining adjacent tasks where the diff remains coherent:

1. Release baseline and source inclusion (Tasks 1–3).
2. Settings migration and path/state/deletion safety (Tasks 4–5).
3. Import error handling and transfer lifecycle (Tasks 6–7).
4. Startup/setup/dashboard completion (Tasks 8–9).
5. Fullscreen core workflows and localization (Tasks 10–11).
6. Dead-code removal and targeted extraction (Tasks 12–13).
7. Documentation, Toolbox, and qualification support (Tasks 14–15).
8. Qualification fixes, then final 1.0 metadata/artifact (Tasks 16–17).

Do not split these into repeated one-test commits, and do not mix unrelated business logic into a release pass.
