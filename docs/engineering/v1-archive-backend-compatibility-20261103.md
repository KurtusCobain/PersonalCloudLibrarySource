# PCLS 1.0 — 7z/RAR .NET 4.6.2 archive backend compatibility gate

Date: November 3, 2026
Status: **isolated CI smoke proven; production support NOT integrated.**

## Decision and scope

Use modern, stable SharpCompress **0.50.7**, via its **netstandard2.0** asset, for continued evaluation. PCLS and Playnite SDK 6.16 still target **.NET Framework 4.6.2**. NuGet reports compatibility but that alone does not guarantee runtime assembly loading.

**Do not** adopt an older vulnerable SharpCompress package just to obtain a direct .NET Framework DLL. Do not install external 7-Zip/RAR executables on the user's machine, invoke arbitrary shell tools from the plugin, or equate magic bytes with a validated archive.

The new isolated project `tools/archive-compatibility/ArchiveCompatibility.csproj` has these independent dependencies:
- `SharpCompress` **0.50.7**
- Explicit `System.Memory` **4.6.3** (net462 asset)
- `Microsoft.NETFramework.ReferenceAssemblies.net462` **1.0.3** (build-time only)
- SharpCompress brings `Microsoft.Bcl.AsyncInterfaces`, `System.Text.Encoding.CodePages`, and transitive runtime assembly dependencies, including .NET Standard facade assemblies.

It uses automatic .NET Framework executable binding redirects. No package references were added to the shipping PCLS project or NUnit test project. The ordinary `.pext` packaging script does not include these experimental runtime assemblies.

## CI evidence

Workflow: `.github/workflows/archive-compatibility.yml`
- Windows-latest builds and executes an **actual net462 executable**, not a modern `net8` substitute.
- Creates a synthetic 7z archive using the runner's 7-Zip fixture tool (CI only).
- Downloads standalone RAR4 and RAR5 fixtures from immutable upstream SharpCompress commit `6128ec51eec4ca9f7b7b9f44b77bdb0cd8b3bd97`, from the upstream repository's `tests/TestArchives/Archives` directory. The next run checks SHA-256 before reading either fixture:
  - `Rar.rar` (RAR4): `60DB161DE57DC59AA12E0C45B1B70D78904DA3D104E74748972AC38643F12802`
  - `Rar5.rar` (RAR5): `3319DE3E8A91A58D08D8A83F48EBAE7E6B022C542B4A58775BAB64F4063988A9`
- Read-only inspection streams actual entries via `SharpCompress.Archives.ArchiveFactory.OpenArchive` and `entry.OpenEntryStream()`; it checks extension/signature agreement, entry paths, duplicate names, <=512 entries, <=64 MiB per member, <=256 MiB total, and exact streamed size. It computes SHA-256 on extracted bytes **without writing any extracted file to disk**.
- A negative gate feeds truncated 7z and RAR5 signatures, which must be rejected rather than being treated as valid archives.
- Inspects side-by-side DLL copies and ensures the shipping `PersonalCloudLibrarySource/packages.config` still contains no SharpCompress or experimental dependency.
- Keeps the NuGet project assets metadata in a short-lived CI artifact; no game/library content or private credentials.

**Successful functional smoke before SHA-pin/negative-case follow-up**:

## Shared read-only production preflight (new integration increment)

- `PersonalCloudLibrarySource/Services/MultiFormatArchivePreflightPolicy.cs` is a **dependency-free, parser-neutral** service compiled into the production PCLS DLL. Its explicit `MultiFormatArchiveEntry` data contract is populated by the **isolated SharpCompress executable**, which links the same source file and `ArchiveInspectionPolicy.cs`. It does **not** expose a Playnite extraction action, write a cache folder, or create ownership or launcher approval.
- A bounded review permits at most **4,096 entries**, **2 GiB per regular file**, **8 GiB declared total**, and a **1,000:1 expansion ceiling**. Entries with missing metadata, encrypted/incomplete/split status, anti-items, link targets, special/reparse POSIX or Windows file attributes, control-character paths, Windows device names, traversal, case-collisions, parent-file conflicts or unsafe compression ratios are refused. Reuse of the shared ZIP path-policy logic ensures consistent Windows filename handling.
- True multi-volume detection uses `IArchive.Volumes.Count()` and requires exactly **one** physical archive volume. **Do not** use SharpCompress `Entry.VolumeIndexFirst/Last` as physical-volume identifiers: the library's `Entry` class derives those values from internal part indexes, and a normal 7z test file returned `1/1`.
- 7z reports `CompressedSize == 0` on `SevenZipEntry` even for valid compressed content; the adapter therefore marks 7z entries as using **shared archive compression** and uses the *whole source archive length* for total expansion-bomb checks. RAR entries retain per-file compressed-byte limits whenever the decoder supplies them. The isolated adapter additionally enforces **512 test entries**, **64 MiB per file**, **256 MiB actual streamed bytes**, and exact declared-versus-decoded lengths.
- The probe hashes the source archive **before and after** read-only inspection through the same Windows source handle and requires its SHA-256 to remain unchanged, while streaming and hashing each decoded member. It also checks archive-level `IsComplete`, `IsEncrypted`, and the actual volume collection before member inspection.
- New NUnit suite `MultiFormatArchivePreflightPolicyTests` covers valid single-volume input, no-write authority, encrypted/incomplete/multipart/linked and anti-item input, Windows and Unix link attributes, invalid path characters, traversal, collisions, parent conflicts, solid compression, size/ratio bombs, empty archives and entry limits. CI also creates an **encrypted-header 7z** fixture using a synthetic test password; this must be rejected without extraction alongside truncated 7z/RAR5 input.

### Residual implementation boundary

This shared pure policy is only a **preflight gate**. It does not trust, execute, extract or atomically publish an archive, and it does not prove that SharpCompress dependencies load under Playnite's real host without an external `.exe.config` binding-redirect file. PCLS's `packages.config`, release packaging and default single-source mode remain unchanged. Production 7z/RAR extraction still requires adapter packaging, host smoke tests, source identity binding, private transactional staging, strict output and file integrity checks, recorded receipts and opt-in UI confirmation.

## Required next coding gates (not yet achieved)

1. Introduce a **read-only multi-format preflight** in the PCLS app. Bind the exact source archive bytes to a review SHA-256; reject encrypted/header-protected, multipart, spanned, linked/reparse-capable, absolute/traversal/ADS/ambiguous Windows path members, excessive entry counts, decompression bombs, inconsistent lengths, unsupported methods and collisions. Do not silently treat RAR or 7z as ZIP.
2. Use a **create-only private staging directory** for 7z/RAR; stream with cancellation, strict per-entry and total sizes, per-entry CRC/integrity where available, a final exact-tree snapshot and SHA-256 revalidation, atomic same-volume publication to an empty destination, and safe failure rollback. Stale read-only review must never authorize changed source bytes.
3. Integrate with existing manifest IDs, explicit user confirmation, ownership V2 receipts, launcher approval/revocation, game install state, maintenance, repair and cancellation. Source-bound multi-source IDs need *separate provenance*; no legacy approval reuse.
4. Verify actual Playnite 6.16 host loading, DLL binding redirects (a class library plugin does **not** control the host `.exe.config`), side-by-side dependency deployment and license/security notices. The isolated console passing is **not proof of plugin-host compatibility**.
5. Add production synthetic 7z/RAR tests for corrupt/multipart/encrypted/linked/traversal and interrupted staging; measure performance and resource budgets; run independent security review and final native Windows acceptance.
